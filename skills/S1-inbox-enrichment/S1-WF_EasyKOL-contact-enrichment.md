# 🛰️ [Process] S1 EasyKOL Contact Enrichment WF

> **本工作流基于 `s1-inbox-enrichment` 技能，只负责 EasyKOL 触发的联系方式增强，不承担平台基础字段补齐。**

## 一、 核心定位 (Scope)

`EasyKOL` 在当前定义中是 **Email 探测层**，而且默认执行口径为 **截图优先**。

本工作流只做：

- 探测 `联系方式`
- 回填 `联系方式备注`
- 为每一行保留 EasyKOL 面板截图证据
- 输出命中 / 未命中 / 异常样本

本工作流不做：

- 不补 `账号ID / 频道/作者名称 / 粉丝数 / 国家 / 语言`
- 不补 `近期10条均播`
- 不提炼商业定位
- 不写客户友好版简介
- 不迁移 S1 -> S2

## 二、 适用场景 (When to Use)

优先在以下情况使用：

- 表中基础字段已经较完整，但 `联系方式` 为空
- 已有 `平台 / 账号链接 / 账号ID`，需要提高 email 命中率
- 需要截图留证，确认 EasyKOL 面板中展示的邮箱
- 用户明确要求“跑 EasyKOL”“用 EasyKOL 补联系方式”“EasyKOL 截图取证”

不建议在以下情况直接使用：

- `账号链接` 大量缺失或异常
- `平台` 无法识别
- `账号ID` 和主页链接明显错位
- 用户实际目标是 Raw -> S1 建表或 S1 -> S2 迁移

## 三、 输入确认 (Input Check)

正式执行前必须确认：

1. 目标表路径
2. 处理范围：全表 / 指定行号 / 指定平台 / 指定分区
3. 是否只补空值
4. 是否需要正式写回主表

若用户没有提供目标表，必须先询问，不得自行猜表。

## 四、 字段写回规则 (Writeback Rules)

| 目标字段 | 写回规则 | 覆盖标准 |
| :--- | :--- | :--- |
| `联系方式` | 仅写入 EasyKOL 面板截图与页面信息共同确认的有效邮箱 | 默认只补空值；若旧值不是有效邮箱且 EasyKOL 命中有效邮箱，可覆盖 |
| `联系方式备注` | 标准备注值仅使用 `EasyKOL获取` 或 `EasyKOL无法获取` | 当 `联系方式` 新增、覆盖或本轮明确未命中时更新 |

禁止：

- 猜测邮箱
- 从昵称、handle、域名拼邮箱
- 把社媒账号、官网 URL、Linktree 当作邮箱写入 `联系方式`
- 用弱文本命中覆盖已经明确可信的人工联系方式，除非用户明确要求

## 五、 执行步骤 (Run Steps)

### Step 1. 筛选待处理行

默认筛选条件：

- `联系方式` 为空
- `平台` 可识别
- `账号链接` 非空

可选加强条件：

- 只处理 `YouTube`
- 只处理 `TikTok`
- 只处理 `Instagram`
- 只处理指定行号范围
- 只处理 `Part2 / Part3`

### Step 2. 每行先截图，再判定邮箱

本工作流默认要求 **每处理一行，都先完成截图取证**。

截图入口：

- `scripts/easykol/s1_easykol_capture_panels.py`

默认截图口径：

1. 打开目标主页
2. 等 EasyKOL 面板异步注入完成
3. 定位右侧面板关键元素
4. 尽量把面板居中到稳定区域
5. 裁 `panel` 与 `emailbox`
6. 保存截图后，再进入邮箱判定

### Step 3. 结合截图与页面文本判定邮箱

主入口：

- `scripts/easykol/s1_easykol_enrichment.py`

默认判定原则：

- 截图证据优先
- 页面文本 / DOM 只作为辅助，不作为弱证据直接写回
- 若邮箱在面板中被拆成 `local-part` 与 `@domain` 两段显示，允许重组
- 若截图中邮箱不清晰，则不得写回

### Step 4. Preview Review

正式写回前必须输出 review 表，至少包含：

- 原行号
- 平台
- 账号ID
- 账号链接
- 原 `联系方式`
- EasyKOL 命中邮箱
- 建议写回的 `联系方式`
- 建议写回的 `联系方式备注`
- 状态：`hit / no_email / error / skipped`
- 证据截图路径

### Step 5. 正式写回

正式写回前必须：

1. 确认写回范围
2. 确认只写 `联系方式 / 联系方式备注`
3. 使用脚本写表，不手工改 CSV

正式写回后必须：

- 输出写回行数
- 输出命中邮箱数量
- 输出未命中数量
- 输出异常数量
- 输出本轮 review / audit 文件路径

## 六、 异常与熔断 (Error Handling)

- 若页面打不开，标记 `EasyKOL页面异常`
- 若 EasyKOL 面板未加载，标记 `EasyKOL面板未加载`
- 若面板无邮箱，写 `联系方式备注 = EasyKOL无法获取`
- 若截图中邮箱不清晰，不写回邮箱
- 若同一批异常率过高，立即熔断并回到筛选阶段
- 若发现目标表缺少 `联系方式` 或 `联系方式备注` 列，停止执行并先修表头

## 七、 输出规范 (Output)

本工作流完成后至少输出：

- 目标表路径
- 处理范围
- review / audit 路径
- 成功命中数
- 未命中数
- 异常数
- 是否已正式写回
