# 🛰️ [Process] Raw -> S1 Inbox 生成 SOP

> **本工作流基于 `s1-inbox-enrichment` 技能，负责把外部来源表格标准化转换为 `【S1 Inbox】` 主表。**

## 一、 输入 (Input)

### Step 1. 接收来源表格

执行本工作流时，用户必须提供至少一份来源表格。

来源表格可以是：

- Excel
- CSV
- 多个 sheet 的混合来源

若用户尚未提供来源表格，必须先向用户索取，再进入后续处理。

### Step 2. 识别目标输出

在开始处理前，需明确本轮目标是生成 `S1 Inbox`，而不是 `RAW`、`S2 Cold` 或其他过程表。

正式输出命名统一使用：

- `【S1 Inbox】{主题名}.csv`

正式输出位置统一为：

- `Agency/list-master/`

### Step 3. 运行前确认去重参考表

每次运行本工作流前，必须先和用户确认本轮去重参考表。

默认去重参考表为：

- `Agency/list-master/【S2 Cold】Rockbase-580-KOL.csv`
- `Agency/list-master/【S2 Cold】Corestar-1000-KOL.csv`

执行前必须明确询问用户：

- 本轮是否仍以上述两张表作为去重参考
- 是否还有其他需要补充纳入去重的表

**在用户确认去重参考范围之前，不进入映射、去重和正式生成。**

## 二、 处理 (Processing)

### Step 1. 先做映射方案，不直接写表

拿到来源表格后，第一步不是直接生成 CSV，而是先给出映射方案。

映射方案必须明确说明：

- 来源字段如何对应到 `S1 Inbox` 标准字段
- 哪些字段可以直接映射
- 哪些字段需要清洗后再映射
- 哪些字段无法安全映射，应留空
- 哪些字段会进入 `备注`

**在用户确认映射方案之前，不进入去重、改写和正式生成。**

### Step 2. 字段映射契约 (Field Mapping)

执行时需统一映射到以下标准字段：

- `分区`
- `备注`
- `账号ID`
- `频道/作者名称`
- `平台`
- `多平台标记`
- `账号链接`
- `语言`
- `博主国家`
- `粉丝数`
- `账号类目标签`
- `账号类目标签__平台抓取`
- `置顶最高播放`
- `近期10条均播`
- `近10条平均ER（按曝光）`
- `近10条平均ER（按粉丝）`
- `rate（USD$)报价`
- `原价`
- `账号简介`
- `账号简介__平台抓取`
- `Sample Content`
- `Latest Activity Proof`
- `粉丝受众`
- `粉丝性别`
- `粉丝年龄`
- `联系方式`
- `联系方式备注`
- `外链__平台抓取`
- `Recommendation`

常见处理规则如下：

| 规范字段 (Canonical) | 常见来源字段 | 处理逻辑 |
| :------------------- | :----------- | :------- |
| `partition` | `分区` | 正式生成 S1 时统一回填，不依赖来源表原值。规则为：有价格=`Part1`；没价格但有联系方式=`Part2`；其余=`Part3`。 |
| `remark` | `备注 / 沟通进度 / 提报反馈 / 更新时间 / 合作状态 / 来源标签` | 非结构化状态信息统一汇总进 `备注`；多个来源用 ` | ` 拼接。 |
| `handle` | `账号ID` | 优先取原 `账号ID`；若该列实际是 URL，则改从 URL 提取 handle。默认统一为带 `@` 的格式；若是 YouTube `channel/UC...` 则保留 `UC...`。 |
| `author_name` | `频道/作者名称 / 对接姓名 / 博主名称` | 填来源表中的作者名称或主页显示名称。 |
| `platform` | `平台` | 强制标准化为 `YouTube / TikTok / Instagram / X`。 |
| `profile_url` | `账号链接` | 强制写主页主链接；必须清理 query 参数和内容页尾巴。 |
| `language` | `语言` | 统一成中文标准表达，如 `英语 / 日语 / 法语 / 中文`。 |
| `country` | `博主国家` | 统一写中文国别。若来源是英文国名，需转中文。 |
| `followers` | `粉丝数` | 若来源是纯数字，允许先读成数值；正式写入 S1 时统一写成 `K/M` 表达。排序时必须先转可比较数值。 |
| `tag_topics` | `账号类目标签` | 保留原业务标签，可直接写入。 |
| `tag_topics_raw` | `账号类目标签__平台抓取` | 仅保留平台原始标签信息；若来源不提供，则留空。 |
| `top_view` | `置顶单条播放量 / 置顶最高播放` | 统一落在 `置顶最高播放`；若来源是 `9.9k / 9,9k / 5.6m`，需转成标准数字并加千分位，如 `9,900 / 5,600,000`。 |
| `avg_10_views` | `近期10条均播` | 统一落在 `近期10条均播`；若来源是缩写表达，需转成标准数字并加千分位。 |
| `rate` | `单条报价 / rate（USD$)报价` | 保留原文，不强制转纯数字；多平台报价说明可原样保留。 |
| `bio` | `账号简介` | 若来源不提供，可留空。 |
| `bio_raw` | `账号简介__平台抓取` | 若本轮不是平台抓取流程，可留空；若无有效来源，必须留空而不是猜测填写。 |
| `contact` | `联系方式` | 仅写拿得到的真实联系方式；找不到统一留空，不得编造。 |
| `contact_note` | `联系方式备注` | 若联系方式来自原始 Excel 导入，可写 `原始Excel导入`；若为空，则备注也留空。 |
| `external_links_raw` | `外链__平台抓取` | 仅记录平台主页可见外链；来源不提供则留空。 |

### Step 3. 去重

映射方案确认后，先去重，再做正式生成。

去重必须包含两层：

1. 对外去重：与既有主表比对
2. 对内去重：来源表格内部去重

默认至少要与以下表格比对：

- `Agency/list-master/【S2 Cold】Rockbase-580-KOL.csv`
- `Agency/list-master/【S2 Cold】Corestar-1000-KOL.csv`

若用户在运行前补充了其他参考表，则必须一并纳入去重。

去重键优先级固定为：

1. `标准化账号链接`
2. `标准化账号ID + 平台`
3. `联系方式` 仅作辅助审计，不单独作为硬删除主键

### Step 4. 基于字段映射契约修改内容

去重完成后，再根据字段映射契约统一修改内容。

强制修改规则如下：

1. `账号ID` 若是 URL，必须提取 handle，不得原样塞回 `账号ID`
2. `账号链接` 若出现多个 URL 粘连，只允许保留首个最明确的主页链接
3. `账号链接` 的 query 参数默认去除，仅保留主页定位所需主路径
4. `Instagram / TikTok / YouTube` 的内容页、`/videos`、`/reels`、`/shorts` 链接，必须回退到主页
5. `粉丝数` 写入 S1 用 `K/M`
6. `置顶最高播放` 和 `近期10条均播` 写入 S1 必须是标准数字加千分位
7. `账号类目标签__平台抓取`、`账号简介__平台抓取`、`外链__平台抓取` 若原表无数据，必须留空
8. `联系方式` 找不到统一留空，禁止编造

### Step 5. 生成分区

正式生成 `【S1 Inbox】` 前，必须统一生成 `分区` 列，并放在 `备注` 前面。

分区规则固定为：

1. `Part1`：`rate（USD$)报价` 有值
2. `Part2`：`rate（USD$)报价` 为空，但 `联系方式` 有值
3. `Part3`：其余全部记录

执行注意：

- `联系方式` 只要存在有效邮箱或有效联系方式文本，即可进入 `Part2`
- `分区` 不依赖来源表原值，必须由 S1 生成逻辑统一回填

### Step 6. 排序

正式生成 `【S1 Inbox】` 前，必须在去重和字段修改完成后做最终排序。

排序规则固定为：

1. 先按分区顺序排序：`Part1 -> Part2 -> Part3`
2. 每个分区内部按平台顺序排序：`YouTube -> TikTok -> Instagram`
3. 每个平台内部按 `粉丝数` 从高到低排序

执行注意：

- 排序时不能直接按 `5.5K / 1.2M` 这类文本排序，必须先转成数值排序键
- 生成 CSV 前可删除临时排序键，不写入正式表头
- 若平台不是 `YouTube / TikTok / Instagram`，默认排在最后

## 三、 输出 (Output)

### Step 1. 生成正式 S1 文件

正式生成后的文件不再用 `【RAW】` 命名，统一使用：

- `【S1 Inbox】{主题名}.csv`

并放入：

- `Agency/list-master/`

### Step 2. 备份

正式写入或覆盖 `list-master` 中任何文件前，必须先做物理备份到：

- `Agency/list-bak/{YYYY-MM-DD}/`

命名格式：

- `{文件名}_bak_{HHMMSS}.csv`

### Step 3. 输出回执

本工作流完成后，至少应输出：

- 正式 `【S1 Inbox】` 文件路径
- 去重统计
- 保留条数
- 关键异常样本
- 备份回执

## 四、 异常与熔断处理 (Error Handling)

- 若用户未提供来源表格，必须先索取，不得自行假设来源
- 若用户尚未确认本轮去重参考表范围，不得开始映射、去重和正式生成
- 若映射方案尚未获用户确认，不得继续执行去重、修改和正式生成
- 若 `账号ID`、`账号链接`、`平台` 三者都无法确定，则该行应进入异常报告，不直接入正式 S1
- 若 `置顶最高播放` 或 `近期10条均播` 无法安全转数字，可保留原值，但必须进入异常报告
- 若去重键清洗后仍不稳定，优先保守保留并标记，不要误删
- 若 `rate（USD$)报价` 和 `联系方式` 都为空，则默认落入 `Part3`

## 五、 文件命名建议 (Naming)

本文件命名为：

- `S1-WF_Raw-to-S1.md`

原因：

- 与现有 `S1-WF_*` 体系保持一致
- 明确来源是 `Raw`
- 明确目标是 `S1 Inbox`
- 明确这是“生成型”工作流
