# X API及抓取工具详细总结

来源：基于 `${ROCKBASE_HOME}/Downloads/X API及抓取工具、OSINT相关内容总结报告.md` 按主题拆分整理。

## 一、X API核心基础信息

### 1.1 API版本区分（V1与V2）

X API分为两个主要版本，核心差异在于功能支持、使用限制和官方维护优先级，具体对比如下：

- **V1（旧版接口）**：多年前推出，目前仅为兼容老项目保留，官方已不再重点维护，未来将逐步关停。核心特点：单次最多可拉取200条推文，1次请求即可完成；速率限制为每15分钟约900次请求；计费按实际返回条数计算，与V2计费标准一致，但功能较少、稳定性未来无保障。
- **V2（新版接口）**：官方主推、未来唯一维护的版本，结构更规范、功能更全面。核心特点：单次最多可拉取100条推文，若需200条需分2次请求（通过pagination_token翻页）；速率限制为免费层每15分钟约300次请求，付费层更高；计费按实际返回条数计算，支持更多新功能，官方客服仅支持此版本。

核心结论：新上手用户一律优先使用V2，避免使用V1（随时可能失效）。

### 1.2 API开通门槛

开通X API需满足以下基础条件，缺一不可：

- 拥有正常可用的X（Twitter）个人账号；
- 账号已绑定手机号（必须，用于验证身份）；
- 邮箱已完成验证；
- 能正常访问developer.x.com（国内需使用代理）；
- 需填写具体、合规、非爬虫用途说明（关键审核点，字数≥250字符，建议聚焦个人学习、工具制作、学术研究，强调非商用、非爬虫，避免被拒）。

开通流程：用X账号登录developer.x.com → 点击Sign up → 填写用途说明 → 提交人工审核（快则几分钟，慢则1-3天）。

### 1.3 API收费标准（2026年3月最新）

X API无免费读数据权限（免费版仅支持每月发1500条推文，无法读取数据），需付费使用，分为两种计费模式：

#### （1）按量付费（Pay-Per-Use，2026新政策，推荐个人/小批量使用）

- 无月费，仅按实际返回条数扣钱；
- 核心单价：读取1条公开推文 = $0.005（约0.036元人民币）；
- 示例：拉取200条推文，费用为200×0.005 = $1（约7.2元人民币），无论使用V1（1次请求）还是V2（2次请求），费用一致（仅按条数计费，与请求次数无关）。

#### （2）固定套餐（旧模式，适合大批量、长期使用）

- Basic套餐：$100/月，每月可读取10,000条推文，200条摊下来约$0.01/条（比按量付费贵一倍）；
- Pro套餐：$5,000/月，每月可读取100万条推文，适合企业级批量抓取；
- Enterprise套餐：定制化价格，无条数上限，提供专属支持，适合超大批量、合规商用需求。

### 1.4 API常见被拒原因

- 用途说明模糊、过短，或明确提及“爬虫”“数据分析”“批量采集”“大数据”等关键词；
- X账号为新注册、无发帖记录、无互动行为（易被风控拒绝）；
- 未绑定手机号或邮箱未验证；
- 用途描述不真实，或涉及违规、商用未说明。

### 1.5 API使用核心注意事项

- 数据范围：仅能获取公开内容，私密账号（private）内容、私信（DM）、删除的推文、阅读量、后台数据、用户隐私信息（邮箱、电话等）均无法获取；
- 速率限制：按请求次数计算，而非条数，例如V1每15分钟900次请求，最多可拉取900×200=18万条/15分钟；
- 合规性：商用用途需走官方API，非商用（个人学习、研究）可灵活选择，但需避免违规抓取。

## 二、X相关抓取工具（含API替代方案）

X相关抓取工具分为三类：官方API配套工具、GitHub开源免费工具、第三方便宜API，具体详情如下：

### 2.1 官方API配套工具（需付费API支持）

- **twitter-kol-discovery**：GitHub开源工具，需调用X官方API v2，核心功能是模糊关键词+多条件筛选KOL，支持昵称/简介/置顶推文模糊匹配，按粉丝数、互动率、领域标签过滤，可导出CSV/JSON，适合批量挖掘KOL。需提供X API的Bearer Token，费用由X API收取，工具本身免费。

### 2.2 GitHub开源免费工具（无需官方API，零成本）

此类工具无需申请X API，无需付费，靠模拟浏览器访问、抓取公开网页数据工作，适合个人、小批量抓取，核心工具如下：

- **snscrape**（最稳、最常用）
  - 核心功能：无需账号、无需API，免费无条数限制，可批量爬取X用户推文、用户信息，支持关键词搜索，可导出文本/CSV/JSON；
  - 用法：一行命令即可实现抓取（如snscrape twitter-user elonmusk > elonmusk_tweets.txt）；
  - 优点：稳定、支持批量、无速率限制（速度稍慢但稳定）；
  - 缺点：纯命令行操作，需具备基础Python环境。

- **Scweet**（Python库，更灵活）
  - 核心功能：需用X账号Cookie登录，可抓取更多数据（点赞/转发/评论），支持多账号轮询，适合批量抓取多博主数据；
  - 优点：免费开源，支持互动数据抓取，灵活度高；
  - 缺点：需提供X Cookie，有一定封号风险（需控制抓取速度）。

- **TwitterXScraper**（Playwright可视化抓取）
  - 核心功能：模拟浏览器滚动，自动加载全部推文，支持导出CSV，无需过多代码，可可视化调试；
  - 优点：操作相对简单，适合不想写复杂代码的用户；
  - 缺点：稳定性略逊于snscrape，抓取速度较慢。

- **Twint**
  - 核心功能：无API，可抓取历史推文、关注/粉丝列表、位置标签，支持批量导出，适合深度挖掘单个博主数据；
  - 优点：免费、无条数限制，数据维度丰富；
  - 缺点：纯命令行，需基础技术能力，偶尔会因X反爬机制失效。

### 2.3 第三方便宜API（官方API替代方案）

此类API为第三方服务商提供，数据来源与官方一致，但价格比官方便宜10-100倍，无需复杂配置，适合不想折腾开源工具、需要稳定抓取的用户，核心推荐如下：

- **TwitterAPI.io**（性价比最高）
  - 价格：$0.15/1000条推文（官方为$5/1000条，便宜33倍），200条仅需$0.03（约0.22元人民币）；
  - 核心功能：支持批量拉取推文、用户信息，按关键词精确搜索，无月费、按量付费，数据实时性较好；
  - 优点：价格极低，稳定、无需维护，拿来就用；
  - 缺点：不支持用户模糊搜索，仅能精确查询（按ID、用户名、关键词）。

- **Apify（托管爬虫，API调用）**
  - 价格：$49/月起，或按计算单元付费，有免费额度；
  - 核心功能：托管式爬虫，无需自己维护，支持批量百万级数据抓取，提供稳定API接口；
  - 适合场景：不想自己维护爬虫、需要高稳定性、大批量抓取的用户。

- **BrightData Twitter Scraper API**
  - 价格：按量付费，$0.001-$0.005/条（按套餐定价）；
  - 核心功能：企业级服务，支持高并发、防封代理，数据完整性高；
  - 适合场景：企业级批量抓取，对稳定性、数据完整性要求高的需求。

## 三、X内容抓取核心方案（精确搜索+模糊搜索）

### 3.1 精确搜索方案（已知博主、关键词、ID）

核心需求：已知博主handle、ID或精确关键词，批量抓取推文、用户信息，方案对比如下：

|方案|是否付费|需要凭证|单次最大条数|稳定性|风控风险|适合场景|
|---|---|---|---|---|---|---|
|官方API v2|是（$0.005/条）|Bearer Token|100条/请求|极高|无|商用、合规、高稳定性需求|
|第三方便宜API|是（$0.15/千条）|API Key|不限（服务商控制）|中高|无|个人低成本批量抓取|
|snscrape|否|无需Cookie/账号|无上限|中|低|偶尔抓取、少量博主|
|Scweet|否|X账号Cookie|无上限|中|中|需要互动数据、批量导出|

### 3.2 模糊搜索方案（找KOL、模糊关键词、昵称/简介匹配）

核心需求：通过模糊关键词（如AI、LLM）、昵称/简介模糊匹配，挖掘领域KOL，核心结论：官方API、第三方便宜API均不支持直接用户模糊搜索，需通过「批量抓取候选用户→本地模糊匹配」实现，方案对比如下：

|方案|是否付费|需要Cookie|模糊能力|数据完整度|稳定性|适合场景|
|---|---|---|---|---|---|---|
|官方API v2|是|否|弱（仅通配符* / ~）|高|极高|仅模糊搜推文，不适合找KOL|
|第三方便宜API|是|否|几乎无|中|中高|不适合模糊找KOL|
|snscrape + 本地模糊|否|否|极强（本地fuzzy匹配）|中|中|低成本、批量找领域KOL|
|Scweet + 模糊筛选|否|是|极强|高|中|精准挖掘领域KOL|
|twitter-kol-discovery|否（工具免费，需API付费）|是|极强|高|中|专门做KOL挖掘，最贴合需求|

### 3.3 模糊搜索核心流程（必看）

无论使用哪种开源工具，模糊搜索找KOL的核心流程均为3步：

1. 广撒网：用关键词、话题、热门推文，批量抓取一批可能相关的博主ID（粗筛，量大、不准没关系）；
2. 拉全量信息：对这批博主，批量拉取昵称、简介、粉丝数、互动数据、近期发帖等信息，保存到本地（Excel/CSV/JSON）；
3. 本地精筛：在本地数据中做模糊匹配（昵称/简介模糊搜索）+ 条件筛选（粉丝量、互动率、活跃度），最终输出精准KOL清单。

## 四、工具选择建议（按需求分类）

- 精确搜索（已知博主/关键词）：
  - 要稳定、合规、商用 → 官方API v2；
  - 要便宜、低成本 → 第三方便宜API（TwitterAPI.io）；
  - 要免费、偶尔用 → snscrape。

- 模糊搜索（找KOL）：
  - 要免费、低成本 → snscrape + 本地模糊匹配；
  - 要精准、专门挖KOL → twitter-kol-discovery（需API付费）或Scweet + 模糊筛选；
  - 要自动化、多平台 → Social Analyzer（跨平台，下文OSINT部分详细说明）。
