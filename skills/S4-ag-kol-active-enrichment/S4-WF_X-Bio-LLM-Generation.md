# S4 WF X Bio LLM Generation

## 目标

把 `账号简介` 的生成，从“纯规则脚本拼句子”升级为：

- 脚本负责编排
- LLM 负责理解与写作
- 规则文件负责约束口径

适用字段：

- `账号简介`

不直接适用于：

- `账号简介__平台抓取`
- `Latest Activity Proof`
- `联系方式`

---

## 设计原则

### 1. 脚本只负责流程，不负责写作

脚本负责：

- 读取 CSV
- 选择目标行
- 汇总证据
- 生成 prompt pack
- 接收 LLM 输出
- 解析 JSON
- 备份并写回主表

LLM 负责：

- 理解 `账号简介__平台抓取`
- 结合 `账号类目标签__平台抓取`、`外链__平台抓取`、`Latest Activity Proof`
- 对知名人物做高置信、低时效风险的表达补强
- 生成一句更自然、更有匹配价值的中文内部简介

### 2. 证据优先

输入优先级：

1. `账号简介__平台抓取`
2. `账号类目标签__平台抓取`
3. `外链__平台抓取`
4. `Latest Activity Proof`
5. `频道/作者名称`
6. 模型对稳定知名人物的高置信常识

### 3. 输出必须结构化

LLM 输出必须是 JSON，最少包含：

- `账号ID`
- `账号简介`
- `confidence`
- `evidence_used`

---

## 标准流程

### Step 1. 生成 LLM 输入包

脚本：

- `scripts/build_x_bio_llm_pack.py`

作用：

- 从主表抽取目标行
- 组装证据
- 输出：
  - `*_bio_llm_input.jsonl`
  - `*_bio_llm_review.md`

### Step 1.5. 分批与子 agent 调度

推荐做法：

- 主控 agent 只负责分批、发包、收结果、质检、回写
- 子 agent 只负责按固定 prompt 生成 `账号简介`
- 不要让每个子 agent 直接改主表，统一由主控 agent 回写

建议批次：

- 默认每组 `15-20` 条
- 当前 `S4 Hot` 这类规模在 `239` 行左右时，推荐按 `20` 条一组
- 如果某批里长 bio 特别多，降到 `10-15` 条更稳

为什么推荐 `20` 条一组：

- 足够并行，速度明显提升
- 单批人工抽查成本仍然可控
- prompt 长度不容易失控
- 某一批出问题时，回滚和重跑代价小

推荐分工：

- 主控 agent：
  - 扫描目标行
  - 生成 JSONL 输入包
  - 按批次切分
  - 派发给多个子 agent
  - 汇总 JSON 输出
  - 抽样质检
  - 执行备份和回写
- Worker A / B / C ...：
  - 只处理自己分到的批次
  - 严格按 JSON 结构输出
  - 不输出解释性散文
  - 不修改别的字段

推荐执行顺序：

1. 主控 agent 先切出 `batch_001` 到 `batch_00N`
2. 先拿 `batch_001` 这类前 `20` 条做小样本验证
3. 验证通过后，再并行派发剩余批次
4. 全部完成后统一回写主表

特殊情况：

- 若 `账号简介__平台抓取` 为空，但 `账号类目标签__平台抓取` 或 `外链__平台抓取` 仍有信息，可继续生成，但 `confidence` 建议降级
- 若核心证据几乎全空，则保守留空，交给人工复核

### Step 2. 用任意 LLM 跑生成

可选方式：

- 直接在聊天窗口逐条处理
- 用批处理接口跑 JSONL
- 用你后续选定的模型 API 跑批量生成
- 用多个子 agent 并行处理多个批次

要求：

- 保持 JSON 输出
- 不得输出解释性散文
- 子 agent 之间不得重复处理同一批
- 每批输出文件名必须和批次号一一对应，便于主控回收

### Step 3. 回写主表

脚本：

- `scripts/apply_x_bio_llm_output.py`

作用：

- 读取 LLM 输出 JSONL
- 按 `账号ID` 匹配主表
- 先做物理备份
- 再只写回 `账号简介`

## 推荐 Prompt 结构

### System Prompt

你是 Rockbase 的 KOL 资产分析助手。你的任务是为 X 账号生成一条中文内部简介，用于后续定位、筛选和产品匹配。

要求：

- 必须优先基于提供的原始证据
- 允许在不冲突时使用你对稳定知名人物的高置信常识
- 不要复制平台 bio
- 不要写成官样文章或模板句
- 不要夸张吹捧
- 输出必须是一句话中文
- 重点回答：
  - 这个人是谁
  - 主要讲什么
  - 更偏什么表达方式
  - 为什么对 Rockbase 的产品匹配有价值
- 如果证据弱，就保守写，不要脑补

### User Prompt

请基于以下证据，为该 X 账号生成一条 `账号简介`。

字段：

- 账号ID：...
- 名称：...
- 平台 bio：...
- 平台类目：...
- 外链：...
- 最新活动：...
- 当前内部标签：...

输出要求：

1. 只输出 JSON
2. JSON 字段必须包含：
   - `账号ID`
   - `账号简介`
   - `confidence`
   - `evidence_used`
3. `账号简介` 只写一句中文
4. 长度尽量控制在 22-48 字
5. 禁止模板化低信息密度表达

---

## 推荐 JSON 输出格式

```json
{
  "账号ID": "@LangChain",
  "账号简介": "LangChain 官方账号，核心讨论 agent engineering 与开发者工作流，适合开发者生态和工具能力传播。",
  "confidence": "high",
  "evidence_used": [
    "账号简介__平台抓取",
    "外链__平台抓取",
    "Latest Activity Proof"
  ]
}
```

## 为什么这套比旧脚本稳

- 不再靠关键词直接拼句
- 能真正利用 `账号简介__平台抓取`
- 知名人物可以获得更准确表达
- 低置信样本可以留给人工复核
- 下次复用时，不需要从头设计 prompt 和回写逻辑
- 可以天然拆成多批，由多个子 agent 并行完成
