# S4 Active KOL Enrichment

本技能服务 `S4 Active` 阶段，也就是把已经建立联系或已有足够素材的 KOL，沉淀成可复用的活跃资产库。

本技能的第一优先功能是：

- 补全 `账号类目标签`
- 补全 `账号简介`

## 适用任务

- 基于 `账号类目标签__平台抓取`、`账号简介__平台抓取` 及辅助字段，补全 `账号类目标签`
- 基于 `账号简介__平台抓取`、`账号类目标签__平台抓取` 及辅助字段，补全 `账号简介`
- 把 `账号简介__平台抓取` 提炼成内部可读简介
- 把 `账号类目标签__平台抓取` 标准化成 Rockbase 内部统一标签
- 生成 `Active KOL` 档案字段
- 补合作状态、跟进判断、简短备注

## 不做的事

- 不把平台主页重新当成主战场
- 不负责 `S1` 的 handle / followers / 联系方式抓取
- 不在没有原始素材时直接幻想客户友好文案

## 读取顺序

1. 先读本文件
2. 再读 [references/s4_active_field_rules.md](references/s4_active_field_rules.md)
3. 处理 `账号类目标签` 或任何 `tag_*` 体系时，必须读 [tag-system/account_category_label_standard.md](tag-system/account_category_label_standard.md)
4. 处理 `账号简介` 时，必须读 [references/account_bio_rewrite_standard.md](references/account_bio_rewrite_standard.md)
5. 若需要理解原始素材来源，再回看 `S1` skill 的 `WORKFLOW.md`

## 核心原则

- `S4` 做提炼，不做原始事实伪造
- `账号类目标签` 与 `账号简介` 必须建立在 `S1` 原始字段之上
- 可以总结、压缩、标准化，但不能编造平台未提供的信息
- 若原始素材不足，标记为空或待补，不强写
- `账号类目标签` 必须使用受控标签池，不允许临场自由发明
- `tag-system/` 是 `S4` 阶段的标签系统本体目录
- `账号简介` 必须是一句话 Rockbase 内部简介，不回填原始 bio 口吻
- 脚本生成的 `账号简介` 默认是草稿层，不等于最终最优表达
- 对知名人物、高价值账号、强信号账号，允许在证据不冲突时做高置信人工/模型润色

## 常见输入字段

- `账号简介__平台抓取`
- `账号类目标签__平台抓取`
- `外链__平台抓取`
- `粉丝受众`
- `粉丝性别`
- `粉丝年龄`
- `联系方式`
- `近期10条均播`

## 常见输出字段

- `账号类目标签`
- `账号简介`
- `内部定位简述`
- `客户友好标签`
- `合作方向`
- `内容风格`
- `适合产品类型`
- `当前关系状态`
- `最新沟通摘要`

## 写作边界

- 先提炼原意，再压缩表达
- 优先写“对客户有用的判断句”，不是堆原文关键词
- 不要把 `S4` 字段写成 `S5 ClientReport` 的最终交付语气
- 若用户明确要交付口径，再切到 `S5`

## 两个核心字段的执行规则

### 1. `账号类目标签`

- 这是 Rockbase 内部的一级摘要标签，不是平台原始标签复制
- 必须从受控词表中选取，不得写成长串关键词
- 建议写成 `一级类目` 或 `一级类目/二级方向`
- 如同时涉及 AI 和其他方向，优先把 `AI` 放在前面
- 若证据不足，不要硬写复杂组合，宁可保守写一级标签

### 2. `账号简介`

- 这是 Rockbase 内部简介，不是平台 bio 直贴
- 必须压缩成一句中文
- 推荐结构：`身份定位 + 核心内容方向 + 受众或商业价值`
- 优先写稳定定位、表达方式、合作适配，不写空泛夸赞
- 若素材只支持很弱判断，应写保守版简介或留空待补
- 不要写成低信息密度模板句，例如：
  - `围绕...输出内容`
  - `账号定位偏...`
  - `整体更偏...`
- 对知名账号，不应故意忽略其稳定公共身份
