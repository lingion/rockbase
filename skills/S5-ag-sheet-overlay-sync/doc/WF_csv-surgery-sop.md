# 🩺 [Data] CSV 字典级精准手术 SOP

**场景**：当 Steve 提供了一段结构化数据（JSON、列表或聊天记录），要求将这些内容补充或合入到一个大型或核心（Master） CSV 文件时。
**核心原则**：**绝对禁止使用 `replace_file_content` 截断式文本编辑，强制通过动态生成运行时（Runtime） Python 脚本进行字典映射注入。**

## 1. 明确靶点与数据清洗 (Preparation)
- **确认文件路径**：明确需要被更新的 CSV 文件绝对路径。
- **提取映射键 (Keys)**：将 Steve 给出的数据转换为易于匹配的格式。分析出作为关联匹配的“主键”（如：`账号ID` 或 `对接姓名/博主姓名`），以及需要更新的“目标列”（如 `账号简介`）。

## 2. 组装“手术探针” (Dynamic Scripting)
此阶段 Friday 需临时生成一段 Python 脚本，脚本包含 3 大核心模块：
*   **模块 A：强制物理备份** (Shutil Backup)
    若目标是 `Agency/list-master/` 下的正式主表，必须先备份至 `Agency/list-bak/{YYYY-MM-DD}/{filename}_bak_{HHMMSS}.csv`；若只是过程型 CSV，则快照可放在 `workbench/{YYYY-MM-DD}/`。
*   **模块 B：加载并映射** (Data Mapping)
    将需要更新的数据作为字典 (`Dict`) 写入脚本中。
*   **模块 C：安全重写** (Safe Override)
    使用 `csv` 模组逐行匹配主键，修改目标列，安全写回原文件。防范所有双引号错位和换行符陷阱。

## 3. 触发操作 (Execution)
// turbo
1. 将生成的 Python 代码保存为临时文件，存放于当日的 workbench 文件夹下，路径规范：`workbench/{YYYY-MM-DD}/csv_surgery_{YYMMDD_HHMMSS}.py`。
2. 使用 `run_command` 执行该 Python 文件。
3. 执行完成后，必须在回复中输出两方面的信息：
    - 📍 **文件锚定**：明确告知 Steve 备份文件和临时 Python 脚本的具体路径，方便审核和回溯。
    - 📊 **注入结果审计**：报告“成功修改了多少行”、“是否有未能匹配上主键的数据”，增强信息透明度。

## 4. 自动质检（QC Gate）— 强制不可跳过

**原则**：每次 CSV 手术完成后，必须立即自动执行三级质检，结果以 Markdown 表格嵌入当次回复。

### 🔍 Level 1 — 覆盖率扫描 (强制)
使用 Python 扫描**本次操作的行号区间**，统计：
- ✅ **已命中**（目标列已有中文值）：数量 + 百分比
- ⚠️ **未覆盖**（仍为原始语言或空白）：数量 + 명细列表（最多10条）
- ❌ **意外空白**：注入后变为空字符串的行（注入倒退检测）

> **止损条件**：覆盖率 < 80% 时，Friday 立即停止并汇报，禁止继续下一批次。

### 🎲 Level 2 — 随机行抽检 (强制)
从本批次范围内每 **50 行**自动取 1 条，输出：`L{行号} [{账号ID}]: {前25字}...`
基于行号取样（非随机数），确保可复现。

### 🛡️ Level 3 — 哨兵语义核验 (每 Batch 至少 3 个)
选取 3 个有明确特征的 ID，核验简介语义是否一致（如 AI博主 → 简介含"AI"）：
- `✅ [{账号ID}]: {前30字}...` 或 `⚠️ 疑似跑行 [{账号ID}]: {前30字}...`

> **回滚触发**：超过 2 个哨兵语义不匹配，立即从当日备份恢复，停止操作。
